# PEKA v0.1.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Project-scoped memory index, project-aware skill lifecycle, learning notices, and a stale-path check for the curator.

**Architecture:** Three new focused modules (`project.mjs`, `memory-index.mjs`, `changes.mjs`) hold the new logic; `handlers.mjs` and `peka.mjs` only wire them into existing hook events and CLI commands. Memory files stay the single source of truth; indexes and notices are derived.

**Tech Stack:** Node ≥ 18 ESM, `node:test`, git CLI. No npm dependencies.

**Spec:** `docs/specs/2026-10-14-peka-v0.1.4-design.md`

## Global Constraints

- Zero npm dependencies; Node ≥ 18; no network.
- Hooks never throw to Claude Code: failures are logged to `state/peka.log`.
- `MEMORY.md` ≤ 190 lines; descriptions clipped to 150 characters.
- Stale at 14, archived at 30 (calendar days for global skills, active project days for project skills).
- `learning_notice`: `weekly` (default) | `each` | `off`.
- Version string `0.1.4` in `plugin.json`, `package.json`, `marketplace.json`, and `setup.json` writes.
- Heavy commands (`npm test`) run one at a time.

## Review Focus

1. Memory file without frontmatter or with a malformed `project:` line → treated as global, still listed in the index.
2. Session started from `$HOME` or a non-git temp dir → no `Current project` line, no `projects.json` entry for home.
3. Git missing or `auto_commit` off with `learning_notice: each` → no message, no crash.
4. `lastNoticeCommit` rewritten away (store re-initialised) → re-seed silently.
5. Memory body mentioning a remote path (`ssh host` line, `user@host:/x`, URL) → not reported as missing.

Each is pinned by a test in the owning task below.
